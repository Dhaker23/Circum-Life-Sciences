## 10. Build result

**FAIL — pre-existing issue (NOT caused by cleanup).**

```
Error: Route segment config is not allowed in Proxy file at "./src/proxy.ts".
Proxy always runs on Node.js runtime.
```

**Root cause:** `src/proxy.ts` exports `const config = { matcher: [...] }` and `const runtime = "nodejs"`. Next.js 16's `proxy.ts` convention does not allow route segment config exports. This is a pre-existing issue from Phase 14 D4 (middleware→proxy rename).

**Impact:**
- `bun run dev` (development server): ✅ WORKS (HTTP 200 verified)
- `bun run build` (production build): ❌ FAILS

**NOT caused by cleanup** — `proxy.ts` was not modified during this task.

**Recommended fix (REQUIRES OWNER APPROVAL):** Remove `export const config` and `export const runtime` from `src/proxy.ts`. The proxy function itself has internal routing logic (early returns for `/api/auth`, `/api/health`, etc.) that handles route matching. The `matcher` was an optimization to skip static assets; without it, the proxy runs on all routes but the internal logic handles it correctly.
